Use `client.l2_snapshots()` when you need complete Level 2 books for market microstructure analysis. The SDK reconstructs standardized `orderbook` snapshots and `orderbook_delta` updates by default.

## Method signature

```python
l2_snapshots(source, market, from_, to, limit=1000)
```

## Parameters

| Parameter | Type | Required | Notes |
| --- | --- | --- | --- |
| source | str | Yes | Source ID |
| market | str | Yes | Normalized market or instrument ID |
| from_ | str/datetime/date/int | Yes | Inclusive start time (ISO 8601, datetime, date, or epoch microseconds) |
| to | str/datetime/date/int | Yes | Exclusive end time (same formats as from_) |
| limit | int | No | Page size (default: 1000) |

**Note:** API key required for historical ranges. Set `POLARIS_API_KEY` environment variable or pass `api_key` to `PolarisClient()`.

## Return value

List of normalized order book snapshot dictionaries.

## Example response

```python
[
    {
        'timestamp': 1704067200000000,
        'venue': 'binance',
        'symbol': 'BTC-USDT',
        'type': 'orderbook',
        'data': {
            'bids': [
                {'price': 43250.00, 'quantity': 1.5},
                {'price': 43249.50, 'quantity': 2.0}
            ],
            'asks': [
                {'price': 43250.50, 'quantity': 1.2},
                {'price': 43251.00, 'quantity': 3.5}
            ]
        }
    }
]
```

## Fields

Materialized L2 rows use the standard event envelope with `type: "orderbook"` and the following fields under `data`:

- `data.bids`: array of bid levels, each with `price` and `quantity`
- `data.asks`: array of ask levels, each with `price` and `quantity`

Bid levels are sorted descending by price, ask levels are sorted ascending. The envelope-level `timestamp` is the snapshot time in UTC microseconds since the Unix epoch.

A snapshot replaces both sides. A delta changes only listed prices, and quantity
zero removes a price. Deltas are not applied until a snapshot has been received,
and state is cleared across coverage gaps and reconnects. Pass
`materialize_orderbooks=False` in Python, `materialize_orderbooks: false` in
Rust, or `materializeOrderbooks: false` in TypeScript to return raw snapshots
and deltas instead.

## Reconstruction lifecycle

1. `orderbook` with bid `100 × 2` initializes the book.
2. `orderbook_delta` with bid `100 × 3` replaces that quantity.
3. `orderbook_delta` with bid `100 × 0` deletes the price.
4. A coverage gap or reconnect clears the reconstructed state.
5. Any following delta is skipped until another `orderbook` snapshot arrives.

## Example

```python
from datetime import datetime, timedelta, timezone
from polaris_data import PolarisClient

end = datetime.now(timezone.utc)
start = end - timedelta(hours=1)

with PolarisClient() as client:
    snapshots = client.l2_snapshots(
        source="binance",
        market="BTC-USDT",
        from_=start,
        to=end,
    )

print(snapshots[:2])
```

## How it works

`client.l2_snapshots()` uses snapshot-first replay: it queries the `/snapshots` endpoint for historical data and reads from local cached files when available. The SDK handles pagination and data normalization automatically.

For more details on snapshot-based queries, see [Snapshots](/reference/snapshots).
