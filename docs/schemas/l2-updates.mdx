Use `l2_updates()` in Python and Rust or `l2Updates()` in TypeScript when you
need the original order book snapshots and sparse deltas. These methods do not
construct a complete book for every update.

Use `OrderbookBuilder.update()` to maintain book state without allocating a
complete result. Call `snapshot()` only when you need sorted bid and ask levels.

## Method signatures

<CodeGroup>
```python Python
l2_updates(source, market, from_=None, to=None, allow_gaps=False)
```

```rust Rust
l2_updates(HistoricalQuery) -> HistoricalStream<StandardEvent>
```

```typescript TypeScript
l2Updates({ source, market, from?, to? }) => Promise<OrderbookEvent[]>
```
</CodeGroup>

## Parameters

| Parameter | Type | Required | Notes |
| --- | --- | --- | --- |
| source | string | Yes | Source ID |
| market | string | Yes | Normalized market or instrument ID |
| from / from_ | string/date/datetime/number | No | Inclusive start time |
| to | string/date/datetime/number | No | Exclusive end time |
| allow_gaps | boolean | No | Python and Rust only. Return covered updates and warn instead of failing on coverage gaps |

If either time boundary is omitted, the SDK resolves a bounded range from
catalog metadata. Explicitly bounded ranges can replay from complete local
coverage without a network request.

## Return value

Python and Rust return single-pass streams. TypeScript returns an array. Legacy
rows retain their original `orderbook`, `orderbook_snapshot`, `l2_snapshot`, or
`orderbook_delta` type. V2 uses only `type: "orderbook"` and distinguishes rows
with `data.is_snapshot`.

An initial snapshot contains both sides of the book. A delta contains only
changed levels:

```json
[
  {
    "timestamp": 1704067200000,
    "source": "binance",
    "market": "BTC-USDT",
    "type": "orderbook",
    "data": {
      "bids": [[43250.0, 1.5], [43249.5, 2.0]],
      "asks": [[43250.5, 1.2], [43251.0, 3.5]]
    }
  },
  {
    "timestamp": 1704067200001,
    "source": "binance",
    "market": "BTC-USDT",
    "type": "orderbook_delta",
    "data": {
      "bids": [[43250.0, 2.25]],
      "asks": [[43251.0, 0.0]]
    }
  }
]
```

A v2 snapshot has `data.is_snapshot: true`; a v2 delta has
`data.is_snapshot: false`. A snapshot replaces both sides. A delta replaces the quantity at each listed
price, and quantity zero removes that price. A delta can omit an unchanged
side in legacy data; v2 provides both side arrays.

## Build complete books on demand

The builder isolates state by `(source, market)`. `update()` returns `false`
for a delta received before its first snapshot; otherwise it updates native
state without constructing a complete book. `snapshot(source, market)` returns
`None` or `undefined` until that book has been initialized.

<CodeGroup>
```python Python
from polaris_data import OrderbookBuilder, PolarisClient

books = OrderbookBuilder()

with PolarisClient() as client:
    for update in client.l2_updates(
        source="binance",
        market="BTC-USDT",
        from_="2024-01-01T00:00:00Z",
        to="2024-01-01T01:00:00Z",
    ):
        books.update(update)

book = books.snapshot("binance", "BTC-USDT")
if book is not None:
    print(book["bids"][:5], book["asks"][:5])
```

```rust Rust
use futures_util::StreamExt;
use polaris_data::{HistoricalQuery, OrderbookBuilder, PolarisClient};

let client = PolarisClient::builder().build()?;
let mut updates = client
    .l2_updates(HistoricalQuery {
        source: "binance".into(),
        market: "BTC-USDT".into(),
        from: Some("2024-01-01T00:00:00Z".into()),
        to: Some("2024-01-01T01:00:00Z".into()),
        allow_gaps: false,
        materialize_orderbooks: false,
    })
    .await?;
let mut books = OrderbookBuilder::new();

while let Some(update) = updates.next().await.transpose()? {
    books.update(&update)?;
}

if let Some(book) = books.snapshot("binance", "BTC-USDT") {
    println!("{} bids, {} asks", book.bids.len(), book.asks.len());
}
```

```typescript TypeScript
import { OrderbookBuilder, PolarisClient } from "polaris-data";

await using client = new PolarisClient();
const books = new OrderbookBuilder();
const updates = await client.l2Updates({
  source: "binance",
  market: "BTC-USDT",
  from: "2024-01-01T00:00:00Z",
  to: "2024-01-01T01:00:00Z",
});

for (const update of updates) {
  books.update(update);
}

const book = books.snapshot("binance", "BTC-USDT");
if (book) console.log(book.bids.slice(0, 5), book.asks.slice(0, 5));
```
</CodeGroup>

Materialized snapshots contain canonical levels:

```json
{
  "bids": [{"price": 43250.0, "quantity": 2.25}],
  "asks": [{"price": 43250.5, "quantity": 1.2}]
}
```

Bids are sorted from highest to lowest price. Asks are sorted from lowest to
highest price.

## Builder methods

| Method | Behavior |
| --- | --- |
| `update(event)` | Mutates book state without constructing a complete book |
| `snapshot(source, market)` | Materializes the current sorted bids and asks |
| `apply(event)` | Compatibility method that updates state and returns a complete book event |
| `clear_book(source, market)` / `clearBook(source, market)` | Removes one book |
| `clear()` | Removes all managed books |

Use `update()` in high-frequency loops. Use `apply()` only when every update
must immediately produce a complete book.

Materializing a v2 delta replaces its bids and asks with the complete current
book but deliberately keeps `data.is_snapshot: false`. This lets downstream
consumers identify the stored row that produced the materialized state.

<Warning>
Do not carry reconstructed state across a known coverage gap. Keep
`allow_gaps=False` for continuous books, or process each covered interval
separately and clear the builder before the next interval.
</Warning>

## L2 updates compared with L2 snapshots

| Method | Output | Use it for |
| --- | --- | --- |
| `l2_updates()` / `l2Updates()` | Original snapshots and sparse deltas | Application-managed state, custom sampling, and low-latency processing |
| `l2_snapshots()` / `l2Snapshots()` | Complete sorted book after every applicable update | Analysis that requires every intermediate full book |

## How it works

L2 updates use snapshot-first historical replay. The SDK reads locally cached
standardized shards when they cover the requested range and downloads missing
coverage when needed. Raw update iteration stays bounded in memory.
